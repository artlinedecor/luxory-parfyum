# Alif Checkout Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement task by task.

**Goal:** Connect cart to Alif hosted checkout and verify sandbox completion safely.
**Architecture:** Server-only Alif client, durable order adapter, authorized recovery/status and signed webhook. Existing cart gains a configuration-driven action and a return page.
**Tech Stack:** Next 16.2.6, React 19, Supabase JS, Node crypto, Vitest.
**Spec:** ../specs/2026-11-06-alifpay-design.md

## Global Constraints

- Never expose credentials, call simulation from app routes, or count sandbox as revenue.
- Read bundled Next docs. No new dependencies or schema changes.
- Preserve existing user changes and Click/Uzum flows.

## Review Focus

- Concurrent/retried creation must call invoice once.
- API timeout and failed mapping persistence must not generate duplicate invoice.
- Wrong amount, order binding or signature cannot mark paid.
- Sandbox cannot activate real fulfilment, Click, or cart clearing.
- Delayed pending responses cannot undo confirmed/refunded state.
